PYNQ-Z2 官方镜像

使用官方 PYNQ-Z2 镜像启动和开发，先验证 Linux 设备接口，再评估 Debian 13 迁移。

架构结论

  • PYNQ-Z2：Zynq Z7020，双核 Cortex-A9，32 位 ARMv7。
  • 官方镜像的发行版和用户空间架构：以 /etc/os-release、uname -m 和 dpkg --print-architecture 为准。
  • 若板上报告 ARMv7 hard-float，Rust 常用目标：armv7-unknown-linux-gnueabihf。
  • 板级启动文件：FSBL/BOOT.BIN、U-Boot、Linux kernel、DTB；官方镜像已经将它们组合好。

下载与写卡

当前课程使用官方 PYNQ-Z2 v3.1.1 镜像：pynq_z2_v3.1.1.zip。

unzip pynq_z2_v3.1.1.zip
ls -lh
sha256sum <解压后的镜像文件>
sudo umount /dev/sdX?* 2>/dev/null || true
sudo dd if=<解压后的镜像文件> of=/dev/sdX bs=4M status=progress conv=fsync
sync

写卡前用 lsblk 确认整卡设备。写卡会覆盖整张 TF 卡，当前系统卡和主机系统盘都不能作为目标。

启动与身份记录

  1. Boot 跳线拨到 SD，连接 PROG-UART Micro USB 和网线后上电。
  2. 串口终端使用 115200 8N1、无流控。
  3. 登录后保存以下输出：
cat /etc/os-release
uname -a
uname -m
dpkg --print-architecture
cat /proc/device-tree/model
cat /proc/cmdline

串口和网络

tty
stty -F "$(tty)" -a
cat /proc/consoles
systemctl list-units 'serial-getty@*'
ip addr
ip route
ping -c 3 <主机或网关地址>

stty 输出中的 speed 是当前登录线路波特率。保存实际串口节点，登录口与业务 UART 可能不是同一设备。

PS 层 SPI/UART 检查

ls -l /dev/ttyPS* /dev/ttyAMA* /dev/serial* 2>/dev/null
ls -l /dev/spidev* 2>/dev/null
find /sys/class/spidev -maxdepth 1 -type l -printf '%f\n' 2>/dev/null
id
getent group dialout
getent group spi

看到 /dev/spidevB.C 才表示 spidev 用户态接口已经暴露。没有节点时记录设备树、内核和 overlay 状态，本课程先不修改它们。

PYNQ 软件检查

command -v python3
python3 -c 'import pynq; print(pynq.__version__)'
printf 'BOARD=%s\n' "$BOARD"
ls -la /home/xilinx 2>/dev/null || true

导入失败时保存完整错误；Rust 的 Linux 用户态练习不依赖 PYNQ Python。需要 Overlay 或 Jupyter 时再处理对应软件环境。

Debian 13 迁移边界

Debian 13 暂时是后续可选实验。当前主线保留官方镜像的启动链、内核和设备树，直接练习 Rust、SPI、UART 和 TCP。等这些模块在官方系统上稳定后，再评估 Debian 根文件系统、内核模块、固件、设备树和启动参数的兼容性。

Lesson 02 · Rust foundations

Rust 表达式、类型与控制流

先不接真实串口，用一个 UART 配置选择器练习 Rust 的基本表达方式。你会把配置值交给函数、让条件产生结果，并在主机和 PYNQ-Z2 的目标构建之间保持同一份源码。

时长 约 2–3 小时主题 类型、表达式、函数、if、for完成标准 配置选择器可构建并输出

本课成果：完成一个无第三方依赖的 UART 配置选择器，能判断波特率档位和帧格式，并用项目中的 Cargo 默认目标生成 ARMv7 可执行文件。

开始前，先回忆

先不查资料，用一句话回答：为什么下面两个程序不能互换运行？主机程序是 ELF 64 位 x86-64，板上程序是 ELF 32 位 ARM。

完成回忆后查看要点

源代码可以相同，但编译目标不同；host 是编译发生的平台，target 是程序准备运行的平台。本课开始关注源代码本身：变量的类型、表达式的值和控制流。

四个 Rust 规则

  1. 绑定默认不可变。
    let baud = 115_200u32; 之后不能给 baud 重新赋值；需要改变绑定时明确写 let mut。
  2. 类型在编译期确定。
    u32、u8、bool 和 &str 不是可以自动互换的“通用值”。
  3. 表达式会产生值。
    if 的两个分支都可以产生一个值；两个分支必须是同一种类型。
  4. 函数签名说明边界。
    fn classify_baud(baud: u32) -> &'static str 明确输入和输出类型，编译器会检查调用方。

这些规则先服务于配置逻辑。所有权、借用和 Result 会在后续专门课程中展开，不需要在本课提前背完。

主阅读材料：Rust 官方《The Rust Programming Language》的常见编程概念和控制流章节。

先分清 frame 和 class

8N1 是 UART 帧格式：8 个数据位，N 表示 No parity（不发送校验位），1 个停止位。它不是“校验位固定为 0”。如果硬件使用固定 0 或固定 1 的 stick parity，通常会单独称为 space parity 或 mark parity；本课不使用它。

一帧通常还包含 1 个起始位：线路空闲时为高，起始位拉低，然后发送数据位（常见 UART 为低位先发），最后发送停止位（高电平）。所以常见的 8N1 每个字节在线路上占 10 个 bit time：1 起始位 + 8 数据位 + 1 停止位。

本课的 class 只是为了练习条件表达式而起的应用层分类，不是 UART 标准配置，也不会改变串口硬件：

  • slow：波特率不超过 9,600。
  • normal：波特率大于 9,600 且不超过 115,200；例如 19,200、57,600、115,200。
  • fast：波特率大于 115,200；例如 1,000,000。

因此你常用的 normal 只是这段练习代码中的标签。真正配置 UART 时，仍要分别设置波特率、数据位、校验方式和停止位；PYNQ-Z2 串口控制台常见的配置是 115200 8N1。

任务 A：写出 UART 配置选择器

在课程工作区的练习目录中创建项目：

cargo new case/uart-config
cd case/uart-config

编辑 src/main.rs，实现下面的行为。先自己写，再对照要求运行；不要直接复制一个完整答案。

  • 定义 baud: u32 = 115_200、data_bits: u8 = 8、stop_bits: u8 = 1 和 parity = "N"。
  • 写函数 classify_baud(baud: u32) -> &'static str：不超过 9,600 返回 slow；不超过 115,200 返回 normal；其他值返回 fast。
  • 用一个 if 表达式得到帧格式：当 data_bits == 8、parity == "N"、stop_bits == 1 时返回 8N1，否则返回 custom。
  • 打印波特率、帧格式和波特率档位。推荐输出形状如下：
baud=115200
frame=8N1
class=normal

注意：if 的每个分支都必须返回同一类型；这里都返回字符串切片 &str。这正是 Rust 在编译期帮你检查配置逻辑的地方。

任务 B：用输入改变结果

不要先增加命令行解析。直接修改三个配置值，每次修改前先预测输出，再运行程序验证：

  1. 把 baud 改为 9_600，预期档位变为 slow。
  2. 把 baud 改为 1_000_000，预期档位变为 fast。
  3. 把 data_bits 改为 7，预期帧格式变为 custom。
  4. 把 let baud 改成先绑定再赋值，观察编译器如何要求 mut；然后恢复成最简单的不可变绑定。
cargo fmt
cargo run
cargo check

本任务的重点是“先预测，再编译”，而不是堆更多功能。把编译器报错完整读一遍，记录错误代码和它指出的变量。

任务 C：把控制流放进数据检查

新增函数 is_supported_baud(baud: u32) -> bool，只接受 9_600、19_200、57_600 和 115_200。在 main 中用 for 遍历这四个候选值，逐个打印是否支持。

for baud in [9_600, 19_200, 57_600, 115_200] {
    println!("{baud}: {}", is_supported_baud(baud));
}

再加入一个不支持的值，例如 1_000_000，确认函数返回 false。这段逻辑以后可以变成串口配置的输入校验；本课暂时只返回布尔值，错误类型留到第 5 课。

任务 D：在两个目标上构建

如果本项目也使用第 1 课的 .cargo/config.toml，项目默认目标就是 ARMv7：

cargo build --release
file target/armv7-unknown-linux-gnueabihf/release/uart-config

需要在主机上运行调试时，临时覆盖为 x86_64：

cargo run --target x86_64-unknown-linux-gnu

本课不要求把程序部署到板上；交叉构建成功即可。若你愿意，也可以把 ARM 产物复制到 PYNQ-Z2，运行后应看到同样的配置输出。

验收清单

  • 能解释 let、let mut 和重新绑定的区别。
  • 能说出 if 作为表达式时，两个分支为什么需要同一类型。
  • classify_baud 和 is_supported_baud 能通过 cargo check。
  • 主机运行输出能随配置值变化，且 ARMv7 release 构建成功。
  • 能指出本课还没有处理无效输入的详细错误原因，并知道这会在 Result 课程中处理。
常见错误与定位方向
  • cannot assign twice to immutable variable：你给不可变绑定重新赋值了；优先考虑重新绑定或明确加入 mut。
  • if and else have incompatible types：两个分支返回类型不一致，例如一个是数字、一个是字符串。
  • mismatched types：检查 u8、u32 和字符串切片是否混用，必要时在绑定处写出类型。
  • 主机直接执行 ARM 程序出现 Exec format error：用 cargo run --target x86_64-unknown-linux-gnu 运行主机版本。

Lesson 01 · Build and deploy

从 AMD64 构建并运行 ARM64 程序

先把“在哪里编译”和“程序要在哪里运行”分开。今天的成果是一支能在主机与 PYNQ-Z2 分别报告自身目标架构的 Rust 程序。

时长 约 2–3 小时主题 Cargo、目标平台、交叉编译完成标准 程序在板上报告 aarch64/linux

本课成果：在 Debian 13 AMD64 主机创建 Rust 项目、构建 ARM64 Linux 可执行文件，并部署到 PYNQ-Z2 上运行。

开始前，先回忆

不查资料，先用自己的话回答：主机（host）和目标（target）分别是哪台机器？在主机上运行的程序，能直接在 ARM64 板子上运行吗？

完成预测后查看自检要点

主机是 AMD64 Debian 13 开发机；目标是 ARM64 Debian 13 的 PYNQ-Z2。默认构建面向主机，目标架构不同的二进制不能直接在板上运行，必须针对 ARM64 构建。

一个程序，两个平台

源代码相同，构建时指定不同目标，Rust 编译器就会生成对应平台的程序。AMD64 主机负责编辑和编译；PYNQ-Z2 负责运行 ARM64 程序。

  1. AMD64 主机编辑 Rust 源码
  2. Rust 目标标准库选择 aarch64 Linux
  3. ARM64 GNU 链接器生成 Linux 可执行文件
  4. PYNQ-Z2部署并运行验收

Rust 官方把 ARM64 GNU/Linux 目标命名为 aarch64-unknown-linux-gnu。它是 Rust 官方支持的目标；交叉编译时除了目标标准库，通常还需要目标链接器。参阅目标说明和rustup 交叉编译指南。

任务：做一个目标探针

新建独立 Cargo 项目 target-probe。它只做一件事：打印编译时的操作系统和 CPU 架构。

  1. 记录主机环境。运行下面命令，记下主机架构和 Rust 工具链版本。 
    uname -m
rustc --version
cargo --version
  2. 创建项目。用 Cargo 初始化项目，然后在 src/main.rs 中实现目标信息输出。 
    cargo new target-probe
cd target-probe

    提示：Rust 标准库的 std::env::consts::OS 和 std::env::consts::ARCH 是编译目标的常量。按自己的代码风格组合并打印它们。

  3. 先在主机运行。 
    cargo run

    自检输出应包含 linux/x86_64。标准库常量见 Rust 标准库文档。

  4. 安装 ARM64 交叉编译器和 Rust 目标标准库。Rustup 当前只装了主机标准库；Debian 提供 ARM64 GNU 交叉编译器包。安装前确认你有管理员权限。 
    sudo apt install gcc-aarch64-linux-gnu
rustup target add aarch64-unknown-linux-gnu

    Debian 包会提供 aarch64-linux-gnu-gcc。本机已安装的 Rust 工具链和这个交叉编译器是两件不同的工具。参阅Debian 包说明。

  5. 告诉 Cargo 使用目标链接器。在项目中新建 .cargo/config.toml，写入： 
    [target.aarch64-unknown-linux-gnu]
linker = "aarch64-linux-gnu-gcc"

    Cargo 支持按 target 配置 linker。参阅Cargo 配置参考。

  6. 构建并检查 ARM64 产物。 
    cargo build --release --target aarch64-unknown-linux-gnu
file target/aarch64-unknown-linux-gnu/release/target-probe
readelf -h target/aarch64-unknown-linux-gnu/release/target-probe

    检查格式是 ELF 64 位、AArch64。Cargo 会把目标产物放到独立的 target 目录。

  7. 部署到 PYNQ-Z2 运行。将占位符替换成你自己的 Linux 用户名和板卡地址。不要把密码发到课程对话中。

    在主机上复制文件：

    scp target/aarch64-unknown-linux-gnu/release/target-probe USER@BOARD_IP:/tmp/target-probe

    仍在主机上，通过 SSH 让板子运行：

    ssh USER@BOARD_IP 'chmod +x /tmp/target-probe'
ssh USER@BOARD_IP '/tmp/target-probe'

    板上输出应包含 linux/aarch64。如果 SSH 尚未配置，先完成文件传输方式确认，再继续部署。

验收清单

  • 主机原生运行时，程序报告 linux/x86_64。
  • file 或 readelf 确认交叉构建结果是 ARM64 ELF。
  • 同一个程序部署到 PYNQ-Z2 后，报告 linux/aarch64。
  • 能解释 Cargo 默认构建目标与 --target 的区别。
常见失败现象与定位方向
  • linker ... not found：检查 Debian 交叉编译器是否安装，以及 Cargo linker 名称是否拼对。
  • Exec format error：目标二进制架构不匹配，重新确认构建命令含有 ARM64 target。
  • Permission denied：检查远端文件执行权限和部署用户权限。
  • 找不到文件但路径确实存在：可能是动态加载器/运行库不匹配；记录错误全文和板上 Debian 信息再排查。

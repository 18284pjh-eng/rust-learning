Lesson 00 · Board bring-up

从 TF 卡启动 PYNQ-Z2 的 Debian 13

先让板子有一个可观察、可恢复的 Linux 系统，再开始 Rust。你会从一张备用 TF 卡开始，保留板级启动链，建立 Debian 13 armhf 根文件系统，并通过串口完成第一次登录。

时长 约 2–3 小时主题 TF 卡、U-Boot、根文件系统、串口完成标准 板上报告 Debian 13 与 armhf

本课成果：在不依赖 HDMI 的情况下，从 TF 卡启动 PYNQ-Z2，完成串口登录，并验证 Debian 13、ARMv7/armhf、以太网和现有设备节点。

先过架构闸门

PYNQ-Z2 的核心是 Zynq Z7020，处理系统使用双核 ARM Cortex-A9。它是 32 位 ARMv7 平台，不是 ARM64/AArch64。PYNQ 官方构建文档也将 Zynq-7000 的架构写作 arm，而把 aarch64 留给 Zynq UltraScale+ 等 64 位平台。

所以本课程的默认 Debian 目标是 armhf，Rust 目标通常是 armv7-unknown-linux-gnueabihf。第 1 课原先的 ARM64 表述会随本课修正。若你现有系统的 uname -m 输出是 aarch64，先不要照抄后续命令，把输出带回课程对话核对。

安全边界：本课默认使用备用 TF 卡。涉及 dd、分区和格式化的命令都只使用你确认过的设备名；不要把系统盘路径直接替换进去。

完成预测后查看自检要点

PYNQ-Z2 的 PS 是 Cortex-A9，运行 32 位 Linux 时通常看到 armv7l，Debian 包架构是 armhf。arm64 和 aarch64 不能作为这块 Zynq-7000 的默认目标。

你需要的材料

  • PYNQ-Z2 和一张备用 TF 卡；官方入门文档建议至少 8 GB。
  • 主机上的 Debian 13 AMD64、读写 TF 卡的 USB 读卡器、网线。
  • 连接板上 PROG-UART Micro USB 口的 USB 线，以及主机上的串口终端程序。
  • 一份官方 PYNQ-Z2 SD 卡镜像，用来验证板级启动链；不要把它当成最终 Debian 13 根文件系统。

先读官方 PYNQ-Z2 Setup Guide，再看PYNQ 官方板卡和镜像页。官方资料确认了 SD 启动跳线、Micro USB-UART、以太网和镜像写入的基本路径。

路线：先保留启动链，再换根文件系统

  1. 官方镜像验证 TF 卡、FSBL、U-Boot、内核、设备树
  2. 架构记录确认 armv7l、armhf 和串口设备
  3. Debian 根文件系统主机生成 Debian 13 armhf
  4. 板上验收复用板级启动文件，串口登录并联网

这条路线把“板子如何启动”与“Linux 用户空间有哪些文件”分开。Debian 文档说明 ARM 启动还需要与平台对应的内核、初始文件系统和设备树；PYNQ 的 SD 构建流程则负责生成 Zynq 的 BOOT.bin、U-Boot、设备树和内核。不要用普通 PC 的 Debian armhf SD 镜像直接覆盖 PYNQ-Z2。

可选的社区参考是PYNQ-Z2 U-Boot 与 Linux 内核记录；它适合理解文件关系，不替代你手上的板卡镜像和串口日志。

任务 A：先让官方镜像启动

  1. 确认 TF 卡设备名。插入备用卡，只观察设备，不要格式化。 
    lsblk -o NAME,SIZE,MODEL,TRAN,MOUNTPOINTS
sudo dmesg --follow

    记下整张卡对应的设备，例如 /dev/sdX 或 /dev/mmcblkX。后续命令使用整盘设备，不使用其中某个分区。

  2. 写入官方 PYNQ-Z2 镜像。先解压下载的镜像，核对文件名和校验值，再把它写到备用卡。下面是 Linux 主机示例；把 /dev/sdX 换成你刚刚确认的设备。 
    unzip pynq-z2-image.zip
sha256sum pynq-z2-image.img
sudo umount /dev/sdX?* 2>/dev/null || true
sudo dd if=pynq-z2-image.img of=/dev/sdX bs=4M status=progress conv=fsync
sync

    写入 TF 卡会覆盖整张卡。PYNQ 官方也明确要求把解压后的镜像写入 MicroSD，而不是把压缩包或镜像文件复制成普通文件。

  3. 设置板卡。Boot 跳线拨到 SD，电源跳线按官方设置，插入 TF 卡；连接 PROG-UART Micro USB 和网线后再上电。串口终端先使用 115200 8N1，若输出乱码，以当前镜像的启动文档为准。
  4. 记录第一次启动。通过串口观察 U-Boot 和 Linux 日志，登录后记录： 
    cat /etc/os-release
uname -a
uname -m
dpkg --print-architecture
cat /proc/device-tree/model
cat /proc/consoles
ip addr

    本课的关键记录应类似：uname -m=armv7l、dpkg --print-architecture=armhf、设备模型包含 PYNQ-Z2 或 Zynq。

任务 B：在主机生成 Debian 13 armhf 根文件系统

  1. 安装主机工具。 
    sudo apt update
sudo apt install debootstrap qemu-user-static binfmt-support rsync \
  parted dosfstools e2fsprogs
  2. 生成 Debian 13 根文件系统。在工作目录操作，不要把输出目录指向已挂载的系统目录。 
    mkdir -p ~/pynq-z2-debian/rootfs
sudo debootstrap --arch=armhf --foreign trixie \
  ~/pynq-z2-debian/rootfs http://deb.debian.org/debian
sudo cp /usr/bin/qemu-arm-static ~/pynq-z2-debian/rootfs/usr/bin/
sudo chroot ~/pynq-z2-debian/rootfs /debootstrap/debootstrap --second-stage

    debootstrap 的第一阶段在 AMD64 主机下载和解包，第二阶段借助 ARM 模拟器完成目标架构配置。你可以把镜像源换成所在网络更快的 Debian 镜像。

  3. 写入基础配置。把串口设备名替换成任务 A 从 /proc/consoles 或启动日志确认的值；不要预设成某个 tty。 
    ROOTFS="$HOME/pynq-z2-debian/rootfs"
echo pynq-z2 | sudo tee "$ROOTFS/etc/hostname"
sudo tee "$ROOTFS/etc/apt/sources.list.d/debian.sources" >/dev/null <<'EOF'
Types: deb
URIs: http://deb.debian.org/debian
Suites: trixie trixie-updates
Components: main
Signed-By: /usr/share/keyrings/debian-archive-keyring.gpg

Types: deb
URIs: http://security.debian.org/debian-security
Suites: trixie-security
Components: main
Signed-By: /usr/share/keyrings/debian-archive-keyring.gpg
EOF
sudo chroot "$ROOTFS" apt update
sudo chroot "$ROOTFS" apt install systemd-sysv openssh-server sudo ca-certificates
sudo chroot "$ROOTFS" passwd

    密码只在板上终端输入，不要贴到课程对话或仓库。首次部署可先只启用串口登录，网络和 SSH 放到串口验收通过后配置。

  4. 保存板级启动文件。把任务 A 中官方镜像的第一分区完整备份到主机，并记录原根分区的文件系统标签、分区号和启动参数。至少保留 BOOT.BIN、image.ub 或拆出的内核/DTB；不同 PYNQ 版本文件名可能不同。 
    sudo mkdir -p /mnt/pynq-boot
sudo mount -o ro /dev/sdX1 /mnt/pynq-boot
find /mnt/pynq-boot -maxdepth 2 -type f -printf '%P\n' | sort
sudo rsync -aHAX /mnt/pynq-boot/ ~/pynq-z2-debian/boot-backup/

    如果启动文件是一个 FIT 镜像（常见名称为 image.ub），不要直接编辑二进制。先保留原件，后续需要调整 root= 时再依据 U-Boot 环境或 FIT 源文件处理。

  5. 部署到新的根分区。推荐使用另一张卡或卡上的新 ext4 分区。格式化前再次运行 lsblk 核对分区；把 Debian 根文件系统同步进去，并从已知可启动的 PYNQ 根文件系统补齐匹配内核版本的模块和固件。 
    sudo mkfs.ext4 -L pynq-root /dev/sdX2
sudo mkdir -p /mnt/pynq-root
sudo mount /dev/sdX2 /mnt/pynq-root
sudo rsync -aHAX --numeric-ids "$ROOTFS"/ /mnt/pynq-root/
# 仅在确认内核版本匹配后再复制：
# sudo rsync -aHAX /mnt/known-good/lib/modules/ /mnt/pynq-root/lib/modules/
# sudo rsync -aHAX /mnt/known-good/lib/firmware/ /mnt/pynq-root/lib/firmware/
sync

    首次练习的目标是理解分区和启动链，而不是盲目覆盖当前可用卡。若 U-Boot 仍指向旧的分区标签或 PARTUUID，系统会停在找不到根文件系统；保留串口日志，下一步再改启动参数。

任务 C：Debian 13 首次启动验收

  1. 先看串口。上电后确认 U-Boot 找到内核和设备树；内核启动后确认根分区挂载成功。遇到停机时，保存从上电开始的完整串口文本。
  2. 验证系统身份。 
    cat /etc/debian_version
uname -m
dpkg --print-architecture
systemctl --failed
ip link
ls -l /dev/ttyPS* /dev/spidev* 2>/dev/null
  3. 验证网络。先用 DHCP 获取地址，再从主机测试 SSH；若设备树已经暴露 SPI/UART 节点，记录节点路径和权限，不要在本课修改设备树。
  4. 写下架构结论。将最终的 uname -m、dpkg --print-architecture、板卡模型、内核版本和根分区来源保存到学习记录。这些信息决定后续 Rust 的 target triple 和 C 交叉编译器。

验收清单

  • 备用 TF 卡能够让 PYNQ-Z2 从 SD 位置启动，串口能看到启动日志。
  • 能解释 BOOT.BIN、U-Boot、Linux 内核、DTB 和根文件系统分别负责什么。
  • 板上 Debian 版本为 13，架构为 armhf，内核架构输出为 armv7l 或与实际系统一致。
  • 能从主机复制一个文件到板上，并通过串口或 SSH 执行验证。
  • 保留了官方启动分区备份和完整串口日志，下一课不再依赖猜测。
常见失败现象与定位方向
  • 完全没有串口输出：检查 Boot 跳线、电源、PROG-UART 口、串口设备和波特率。
  • Done 灯不亮：先恢复官方 PYNQ 镜像，确认 TF 卡写入目标和镜像完整性。
  • U-Boot 能启动但找不到根文件系统：检查 root=、分区标签/PARTUUID、ext4 文件系统和串口完整日志。
  • Exec format error：把它当作架构不匹配，检查 uname -m 与根文件系统架构；不要先重装 Rust。
  • 系统能启动但没有 SPI/UART 节点：记录设备树、内核和 overlay 来源，留到设备访问课程处理。

带回来的结果

把以下内容发回课程对话：cat /etc/os-release、uname -a、uname -m、dpkg --print-architecture、cat /proc/device-tree/model，以及失败时从上电开始的串口日志。不要发送密码、令牌、私钥或完整网络配置。

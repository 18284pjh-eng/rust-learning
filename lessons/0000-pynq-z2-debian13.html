Lesson 00 · Board bring-up

从 TF 卡启动官方 PYNQ-Z2 镜像

先使用官方镜像把板级启动、串口、网络和 Linux 设备接口跑通，再开始 Rust。Debian 13 保留为后续可选迁移目标，当前课程直接在官方 PYNQ 系统上开发和验收。

时长 约 2–3 小时主题 TF 卡、U-Boot、PYNQ Linux、串口完成标准 官方镜像启动并可开发

本课成果：从 TF 卡启动 PYNQ-Z2，完成串口登录，确认实际 Linux 架构，并检查以太网、SPI、UART 和 PYNQ 软件环境，为下一课交叉编译 Rust 做准备。

先过架构闸门

PYNQ-Z2 的核心是 Zynq Z7020，处理系统使用双核 ARM Cortex-A9。它是 32 位 ARMv7 平台，不是 ARM64/AArch64。PYNQ 官方构建文档也将 Zynq-7000 的架构写作 arm，而把 aarch64 留给 Zynq UltraScale+ 等 64 位平台。

官方 PYNQ 镜像通常应报告 armv7l 和 armhf，但本课以板上实际输出为准。第 1 课默认使用 armv7-unknown-linux-gnueabihf；如果你的镜像报告其他架构，先把输出带回课程对话再选择 Rust target。

当前路线：官方镜像就是当前开发系统。不要在本课执行 Debian 根文件系统替换、分区格式化或修改 U-Boot；这些属于后续可选的系统迁移专题。

完成预测后查看自检要点

登录官方镜像后，先用 uname -m、dpkg --print-architecture 和 cat /etc/os-release 记录事实。CPU 架构、发行版名称和 PYNQ 软件版本是三个独立信息。

你需要的材料

  • PYNQ-Z2 和一张备用 TF 卡；官方入门文档建议至少 8 GB。
  • 主机上的 Debian 13 AMD64、读写 TF 卡的 USB 读卡器、网线。
  • 连接板上 PROG-UART Micro USB 口的 USB 线，以及主机上的串口终端程序。
  • 官方 PYNQ-Z2 v3.1.1 镜像：pynq_z2_v3.1.1.zip。

先读官方 PYNQ-Z2 Setup Guide，再看PYNQ 官方板卡和镜像页。官方资料确认了 SD 启动跳线、Micro USB-UART、以太网和镜像写入的基本路径。

路线：先用能工作的官方系统学习 Rust

  1. 写入官方镜像验证 TF 卡、FSBL、U-Boot、内核、设备树
  2. 记录系统事实确认架构、发行版、内核和串口
  3. 检查 Linux 接口确认 SPI、UART、以太网和权限
  4. 开始 Rust 开发主机交叉编译，板上部署验收

PYNQ 官方 SD 构建流程会生成 BOOT.bin、U-Boot、设备树、Linux 内核和 PYNQ 根文件系统。保留这套完整启动链，可以先把课程重点放在 Rust、Linux 用户态接口和 TCP 通信上。

Debian 13 迁移暂时不进入主线。等 SPI、UART 和 TCP 模块已经有可运行的 Rust 版本，再单独评估内核、设备树、模块、固件和用户空间的兼容性。

任务 A：先让官方镜像启动

  1. 确认 TF 卡设备名。插入备用卡，只观察设备，不要格式化。 
    lsblk -o NAME,SIZE,MODEL,TRAN,MOUNTPOINTS
sudo dmesg --follow

    记下整张卡对应的设备，例如 /dev/sdX 或 /dev/mmcblkX。后续命令使用整盘设备，不使用其中某个分区。

  2. 下载、解压并核对镜像。文件名以官网下载内容为准，不要猜测解压后的扩展名。 
    unzip pynq_z2_v3.1.1.zip
ls -lh
sha256sum <解压后的镜像文件>
  3. 写入备用 TF 卡。把 /dev/sdX 换成你刚刚确认的整卡设备。 
    sudo umount /dev/sdX?* 2>/dev/null || true
sudo dd if=<解压后的镜像文件> of=/dev/sdX bs=4M status=progress conv=fsync
sync

    写入 TF 卡会覆盖整张卡。PYNQ 官方要求把解压后的镜像写入 MicroSD，而不是把压缩包复制成普通文件。

  4. 设置板卡并打开串口。Boot 跳线拨到 SD，电源跳线按官方设置，插入 TF 卡；连接 PROG-UART Micro USB 和网线后上电。串口终端使用 115200 8N1、无流控。
  5. 登录后记录系统身份。 
    cat /etc/os-release
uname -a
uname -m
dpkg --print-architecture
cat /proc/device-tree/model
cat /proc/cmdline

    把输出保存到学习记录。不要把官方系统直接称为 Debian 13；以 /etc/os-release 的实际内容为准。

任务 B：确认官方 PYNQ 开发环境

  1. 确认 PYNQ 软件是否可用。 
    command -v python3
python3 -c 'import pynq; print(pynq.__version__)'
printf 'BOARD=%s\n' "$BOARD"
ls -la /home/xilinx 2>/dev/null || true

    如果 Python 导入失败，记录完整错误即可；这不妨碍先进行 Rust Linux 用户态练习。后续需要 Overlay 时再处理 PYNQ Python 环境。

  2. 确认串口登录线路。 
    tty
stty -F "$(tty)" -a
cat /proc/consoles
systemctl list-units 'serial-getty@*'

    登录终端通常会显示为 /dev/ttyPS0 或同系列设备；stty 输出中的 speed 是当前线路波特率。

  3. 确认网络。 
    ip addr
ip route
ping -c 3 <主机或网关地址>

    先确保主机和板子能通过网线互通，后续 Rust 程序会由板子作为 TCP client 连接主机 server。

任务 C：检查 PS 层 SPI 和 UART 接口

  1. 列出串口节点。 
    ls -l /dev/ttyPS* /dev/ttyAMA* /dev/serial* 2>/dev/null
find /sys/class/tty -maxdepth 1 -type l -printf '%f\n' | sort

    记录实际存在的设备名和权限。PROG-UART 登录口与后续业务 UART 可能不是同一个节点。

  2. 列出 SPI 节点。 
    ls -l /dev/spidev* 2>/dev/null
find /sys/class/spidev -maxdepth 1 -type l -printf '%f\n' 2>/dev/null

    能看到 /dev/spidevB.C 才表示 spidev 用户态接口已暴露；没有节点时先记录设备树、内核和 overlay 状态，本课不修改它们。

  3. 确认普通用户权限。 
    id
getent group dialout
getent group spi

    后续 Rust 程序应使用普通用户运行。若节点权限不允许访问，记录节点属主、属组和权限，下一课再处理。

验收清单

  • 官方 PYNQ-Z2 镜像可以从 SD 启动，串口能看到启动日志并完成登录。
  • 保存了 /etc/os-release、uname -a、uname -m 和板卡模型输出。
  • 确认了串口波特率、以太网地址，以及实际存在的 SPI/UART 设备节点。
  • 知道官方 PYNQ 系统与 Debian 13 的差别，当前不把 Debian 迁移作为 Rust 主线阻塞项。
  • 保留了官方 TF 卡镜像文件，后续系统实验可以用另一张卡进行。
常见失败现象与定位方向
  • 完全没有串口输出：检查 Boot 跳线、电源、PROG-UART 口、串口设备和 115200 8N1。
  • Done 灯不亮：重新检查镜像完整性、写卡目标和 TF 卡连接。
  • 没有 /dev/spidev*：记录设备树、内核和 overlay 来源，不要直接创建空设备节点。
  • 没有业务 UART 节点：确认登录串口与业务串口的区别，并保存 dmesg 中的 tty 日志。
  • Exec format error：检查 uname -m 和第 1 课选择的 Rust target。

带回来的结果

把以下内容发回课程对话：cat /etc/os-release、uname -a、uname -m、dpkg --print-architecture、cat /proc/device-tree/model、ls -l /dev/ttyPS* /dev/spidev* 的输出，以及失败时从上电开始的串口日志。不要发送密码、令牌、私钥或完整网络配置。
